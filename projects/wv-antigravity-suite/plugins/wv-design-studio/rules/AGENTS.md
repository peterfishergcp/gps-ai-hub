# WV Design Studio — Standing Rules

When creating or updating dashboards (`/wv-dashboard`), slide decks (`/slides`), or branded documents/flyers (`/doc-design`), follow these rules at all times:

## 1. Mandatory Visual Preview & 1-Click Browser Launch (NEVER Show Raw HTML Source Code!)
- **Why This Matters:** In Antigravity, clicking a workspace file link like `[index.html](file:///.../workspace/index.html)` opens the **Code Editor** (`</> index.html` raw source code), which confuses business users. Similarly, running `open index.html` via a terminal command triggers an intimidating `Allow open ...?` confirmation prompt.
- **What You MUST Do Instead on EVERY `/wv-dashboard`, `/slides`, and `/doc-design` Turn:**
  1. **Create a Self-Contained Rendered HTML Artifact in the Conversation Artifact Directory (`<appDataDir>/brain/<conversation-id>/`):**
     - Use your native `write_file` tool (NOT `cp` or shell scripts, which skip `ArtifactMetadata`) to write a **100% self-contained single-file HTML copy** (all CSS, JS, and data inlined—for dashboards, read `<target>/dashboard-standalone.html` generated by `scaffold_dashboard.mjs`; for slides and flyers, use the self-contained `deck.html` / `flyer.html`) directly to `<appDataDir>/brain/<conversation-id>/<deliverable_slug>.html` with:
       `ArtifactMetadata: { Summary: "Interactive rendered preview of ...", UserFacing: true, RequestFeedback: false }`.
     - Clicking this **Artifact Card** in chat opens the **rendered visual dashboard, slide deck, or flyer** in Antigravity's right-hand Side Pane—never raw source code!
  2. **Register in the Built-In `WV Preview` Sidecar & Create a 1-Click `.url.json` Launch Card:**
     - Run `scaffold_dashboard.mjs` (for dashboards) or `node <wv-design-studio-plugin-dir>/scripts/register_deliverable.mjs --file <html_path> --kind <slides|doc> --title "<Title>"` (or write `~/.gemini/config/plugin_data/wv-design-studio/deliverables.json`).
     - This registers the deliverable with the built-in **`WV Preview` (`wv-design-preview`)** sidecar running on `http://127.0.0.1:4175/view/<id>`.
     - Use `write_file` to create a URL Artifact (`<appDataDir>/brain/<conversation-id>/Open <Deliverable Name> in Browser.url.json`) with `ArtifactMetadata: { Summary: "1-click browser launch", UserFacing: true, RequestFeedback: false }` containing `{"url": "http://127.0.0.1:4175/view/<id>", "title": "Launch <Deliverable Name> in Browser", "description": "Opens the live rendered view in Chrome/Edge with zero terminal prompts"}`.
  3. **In Your Chat Response (Inline `<agent-embed>` + Rendered Links Only — ZERO Workspace `</> index.html` Links!):**
     - Include `<agent-embed src="file:///<appDataDir>/brain/<conversation-id>/<deliverable_slug>.html"></agent-embed>` directly in your response so the user sees the rendered visual preview inline in chat immediately.
     - Every clickable link in your chat bullets **MUST** point to either:
       - `[Open Rendered Preview in Side Pane](file:///<appDataDir>/brain/<conversation-id>/<deliverable_slug>.html)` (pointing to the **Artifact Directory** path so clicking it opens the **rendered visual preview**, never the code editor!), or
       - `[Launch in Browser (Chrome / Edge)](http://127.0.0.1:4175/view/<id>)` (pointing to the `WV Preview` loopback URL).
     - **STRICT PROHIBITION:** **NEVER** output a markdown `file://` link to a workspace `.html`, `.css`, or `.js` file (such as `[index.html](file:///.../dashboard/index.html)`, `[deck.html](file:///...)`, or `[flyer.html](file:///...)`), because Antigravity renders workspace file links as `</> index.html` chips that open raw source code in the Code Editor! If you mention workspace file names, write them in plain backticks (`dashboard.config.json`) without a `file://` link.

## 2. Preserve Visual Edits (`dashboard.config.json` Is Source of Truth)
- Always read `dashboard.config.json` from disk immediately before editing it so you never overwrite layout spans, card order, titles, or theme colors the user saved visually.
- Whenever you update `dashboard.config.json` or `data/snapshot.json`, re-run `node <skill_dir>/scripts/scaffold_dashboard.mjs --target <target_dir> --sync` (or update both `index.html` and `dashboard-standalone.html`) and update the `<appDataDir>/brain/<conversation-id>/<dashboard_slug>.html` artifact so both the Side-Pane visual artifact and `http://127.0.0.1:4175` preview reflect the latest state.

## 3. Official West Virginia Brand Defaults & Screenshot Emulation
- Default palette when no reference screenshot is supplied: WV Navy `#053254`, WV Rust `#C1452C`, WV Gold `#D5A245`, neutral `#F4F6F8` / `#FFFFFF`, `Fira Sans` typography.
- When the user shares a screenshot or brand PDF, extract its exact hex tokens and density into `dashboard.config.json` (or slide/flyer CSS variables).

## 4. Zero Unsafe DOM Sinks & Read-Only Parameterized SQL
- Never use `innerHTML`, `outerHTML`, `insertAdjacentHTML`, or `document.write` in generated JS; construct DOM/SVG nodes via `createElement`, `createElementNS`, and `textContent`.
- Enforce read-only `SELECT` / `WITH ... SELECT` SQL with parameterized inputs (`@param`) and `maximumBytesBilled` cost caps on BigQuery; bind any local preview server strictly to `127.0.0.1`.
