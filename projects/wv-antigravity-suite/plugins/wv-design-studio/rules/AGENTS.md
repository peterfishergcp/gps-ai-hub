# WV Design Studio — Standing Rules

When creating or updating dashboards (`/wv-dashboard`), slide decks (`/slides`), or branded documents/flyers (`/doc-design`), follow these rules at all times:

## 1. Mandatory Serverless Visual Artifact Preview (ZERO `127.0.0.1` URL Cards & ZERO Raw `</> index.html` Code Links!)
- **Why This Matters on State Corporate Laptops:**
  1. Locked-down corporate laptops do **not** have Python or Node web servers running, and local firewall rules block arbitrary `127.0.0.1:<port>` listeners—so `.url.json` artifacts pointing to `http://127.0.0.1:...` fail with `ERR_CONNECTION_REFUSED`.
  2. Clicking a workspace file link (`[index.html](file:///.../workspace/index.html)`) inside Antigravity opens the **Code Editor** (`</> index.html` raw source code), which confuses business users.
  3. By contrast, **self-contained `.html` files saved directly in the Conversation Artifact Directory (`<appDataDir>/brain/<conversation-id>/<name>_preview.html`) with `ArtifactMetadata: { UserFacing: true }`** render visually right inside Antigravity's built-in Side-Pane Viewer with **zero web server, zero Python, zero Node, and zero firewall ports**!
- **What You MUST Do on EVERY `/wv-dashboard`, `/slides`, and `/doc-design` Turn:**
  1. **Write ONLY Self-Contained `.html` Artifacts to `<appDataDir>/brain/<conversation-id>/` (`UserFacing: true`):**
     - Use your native `write_file` tool (never `cp` or shell scripts, which skip `ArtifactMetadata`) to write a **100% self-contained single-file HTML copy** (all CSS, JS, and data inlined—for dashboards, read `<target>/dashboard-standalone.html` generated by `scaffold_dashboard.mjs`; for slides and flyers, use the self-contained `deck.html` / `flyer.html`) directly to `<appDataDir>/brain/<conversation-id>/<deliverable_slug>_preview.html` with:
       `ArtifactMetadata: { Summary: "Interactive rendered preview of ...", UserFacing: true, RequestFeedback: false }`.
     - If a prompt asks for all 3 deliverables (Dashboard, Slide Deck, and Stakeholder Flyer), create **all 3** as `.html` Artifacts in `<appDataDir>/brain/<conversation-id>/`:
       - `<slug>_dashboard_preview.html` (`UserFacing: true`)
       - `<slug>_slides_preview.html` (`UserFacing: true`)
       - `<slug>_flyer_preview.html` (`UserFacing: true`)
  2. **STRICT PROHIBITIONS:**
     - **NEVER create `.url.json` artifacts pointing to `http://127.0.0.1:...` or `http://localhost:...`** (unless the user explicitly asks to start a live BigQuery Node server).
     - **NEVER start `python3 -m http.server`** (corporate laptops do not have Python installed).
     - **NEVER output a `file://` link to a workspace `.html`, `.css`, or `.js` file** in chat (such as `[index.html](file:///.../dashboard/index.html)`), because workspace links open raw source code in the Code Editor!
  3. **In Your Chat Response:**
     - Embed `<agent-embed src="file:///<appDataDir>/brain/<conversation-id>/<deliverable_slug>_preview.html"></agent-embed>` inline and link **ONLY** to the `<appDataDir>/brain/<conversation-id>/<deliverable_slug>_preview.html` Artifact(s) (`[Open Rendered Preview in Side Pane](file:///<appDataDir>/brain/<conversation-id>/<deliverable_slug>_preview.html)`).
     - Remind the user they can also click **`Open / Download HTML ↗`** (or **`Print / Save as PDF`**) in the top toolbar of the rendered preview to open the standalone file in Chrome or Edge with zero web server required.

## 2. Preserve Visual Edits (`dashboard.config.json` Is Source of Truth)
- Always read `dashboard.config.json` from disk immediately before editing it so you never overwrite layout spans, card order, titles, or theme colors the user saved visually.
- Whenever you update `dashboard.config.json` or `data/snapshot.json`, re-run `node <skill_dir>/scripts/scaffold_dashboard.mjs --target <target_dir> --sync` and update the `<appDataDir>/brain/<conversation-id>/<dashboard_slug>_preview.html` artifact.

## 3. Official West Virginia Brand Defaults & Screenshot Emulation
- Default palette when no reference screenshot is supplied: WV Navy `#053254`, WV Rust `#C1452C`, WV Gold `#D5A245`, neutral `#F4F6F8` / `#FFFFFF`, `Fira Sans` typography.
- When the user shares a screenshot or brand PDF, extract its exact hex tokens and density into `dashboard.config.json` (or slide/flyer CSS variables).

## 4. Zero Unsafe DOM Sinks & Read-Only Parameterized SQL
- Never use `innerHTML`, `outerHTML`, `insertAdjacentHTML`, or `document.write` in generated JS; construct DOM/SVG nodes via `createElement`, `createElementNS`, and `textContent`.
- Enforce read-only `SELECT` / `WITH ... SELECT` SQL with parameterized inputs (`@param`) and `maximumBytesBilled` cost caps on BigQuery.
