# Corner Cases and Connector Fallbacks

Use this list when a request or a search result doesn't fit the main workflow in
`SKILL.md`. Tables: 1 Matched Documents, 2 Must Redact, 3 Needs Officer Review
(including every "Not sure" file, numbered after the matched documents). Clear
non-matches are counted in the "other files" sentence after Table 1, not listed.

## Special Requests

These cases are named in `SKILL.md` (Jurisdiction first and Policy check).

-   Federal courts and Congress are not covered by FOIA, and no state public
    records law applies to them either: say so, note the body may have its own
    access policy, name the designated officer (who handles records requests for
    that body) as the decider, and search only locations the user names.
-   Police and other criminal justice records: some states cover them under a
    separate law, not the general public records act. Name that law only when
    you are sure it applies, with "provision to confirm"; otherwise name the
    state's general public records law and flag that another law may apply.
    Never carry one state's rules or exemptions over to another state.
-   Federal request for one's own records: the Privacy Act covers only U.S.
    citizens and lawful permanent residents (5 U.S.C. § 552a(a)(2)); flag
    unclear status or an unclear subject (then treat it as third-party).
-   Too vague: nothing specific to search for, only generic words ("everything",
    "all records", "emails about money") and no subject, program, office,
    people, or period. Say it may not meet the reasonable-description standard
    and that the officer decides, list questions the officer may want to ask the
    requester, and search nothing, even in a location the user named or when
    search results are already in the conversation. No tables. Draft no letter.
-   Very large or broad: what to look for is clear, but the scope has no limits
    (many custodians or thousands of items, for example "all emails mentioning
    SNAP across the agency for 10 years"; or a record type with no subject or
    period, for example "all contracts, invoices, and change orders" or
    "settlements"). Note the reasonable-description issue, suggest narrowing
    questions (which subject, vendor, project, or office; what period), search
    only locations the user names (with the full report for them), and keep Gaps
    to list the organization-wide search ("ask the agency's IT team whether an
    organization-wide search is possible") and the agency's full records process
    or records team. No denial, fee, or scope letter.
-   State courts and legislatures are often outside the state's public records
    act and may follow their own access rules: say so, name the designated
    officer as the decider, and search only locations the user names.
-   Tribal governments, the District of Columbia, and U.S. territories have
    their own laws; federal FOIA and state acts don't cover tribes. Name the law
    only when you are sure; otherwise ask, and leave it to the officer.
-   Private businesses and nonprofits: public records laws generally cover
    public bodies, not private ones (some states reach records of contractors
    doing public work). Say so, leave coverage to the officer or counsel, and
    search nothing unless the user confirms the records are an agency's.
-   Foreign governments (outside the United States): this skill covers U.S.
    federal and state public records laws only. Say so and ask the user to
    confirm the agency; search nothing.
-   A request addressed to a different agency than the user's: say so in the
    Request Summary; whether to refer it is the officer's decision; search only
    locations the user names.
-   Several unrelated requests in one message (different requesters or
    subjects): list each in one line and ask which to start with; search nothing
    yet. Numbered parts of one request are handled together.
-   A message that asks for no records (a complaint, a service request, a
    question to staff): say so in one sentence and suggest where it goes (for
    example, the agency's service line); never repeat a private name, address,
    or phone number from it.
-   Dates that can't be right (the end before the start): if one reading is
    plainly a typo, use it, say so in the Request Summary, and note that it
    needs confirming with the requester; otherwise ask.
-   The user asks to report that no records exist, to leave out found files, or
    to skip files already found: decline in one sentence; the report shows what
    was searched and found, and the officer decides the response.
-   The user asks to search the web, news, or other public sources: say in one
    sentence that this skill searches only connected systems and uploads, and
    add a Gaps row suggesting the officer check those sources.

## Connector fallbacks

Situation                                                                                               | Where it goes             | What the reply says
------------------------------------------------------------------------------------------------------- | ------------------------- | -------------------
Source returns 401 or 403, or is disconnected                                                           | Gaps                      | The source and error; nothing retrieved; who could get access or run the search. Never worked around
Source times out                                                                                        | Gaps                      | Retried once; whether the retry worked and what it returned
Source returns a server error (5xx) or a rate limit                                                     | Gaps                      | Retried once; whether the retry worked; the search is incomplete if it didn't
Source returns a capped or partial list                                                                 | Gaps                      | "First N shown"; the search is incomplete; how to see the rest
Source returns 0 items                                                                                  | Gaps                      | "0 items" with the terms and dates; not a finding that no records exist
A named folder can't be listed or searched with no terms                                                | Extra searches, then Gaps | Search the folder for each record type asked for without the identifier; sort every file returned; Gaps says the whole folder could not be confirmed and which searches ran
One item returns an error (for example, 403 on open)                                                    | Table 3                   | "Not sure it matches: couldn't open", with who could open it
One item has no readable text, or an email's only possibly matching content is an unreadable attachment | Table 3                   | "Not sure it matches: can't be read"
One item carries a Restricted label                                                                     | Table 3                   | "Not sure it matches: Restricted label; not opened", that reason only
Part of a matched item can't be read (for example, an attachment)                                       | Table 3                   | "Part couldn't be read"; Table 2 covers only what was read

Never reconstruct content that was not retrieved, and never present a failed,
partial, or capped search as complete.

## Hand-off to public-records-redaction

"Redact items 1 and 5 from this report" or "Prepare items 1 and 2 for release"
uses the latest report's # column (a Table 1 number, or a "Not sure" number
listed only in Table 3). `public-records-redaction` reviews every picked item in
full, not only the Table 2 kinds, and carries its Table 3 reasons as flags.
