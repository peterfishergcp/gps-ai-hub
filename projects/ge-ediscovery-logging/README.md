## Overview

Regulated enterprises deploying **Gemini Enterprise** (Google Cloud Discovery Engine) and **NotebookLM Enterprise** with **Workforce Identity Federation (WIF)** (such as Microsoft Entra ID, Okta, or Ping Identity) often require **100% server-side eDiscovery and compliance archival** of:
1. **User Prompts & Full Model Responses** (`prompt_text` and `response_text` across Gemini Enterprise chat sessions, Deep Research reports, custom No-Code/ADK agents, and NotebookLM Enterprise notebooks)
2. **Model Reasoning / Chain-of-Thought** (`thought_text`)
3. **User-Uploaded Attachments (`USER_PROVIDED`)** (PDFs, Word documents, spreadsheets, text files, images — with automatic magic-byte MIME detection)
4. **AI-Generated Artifacts (`AI_GENERATED`)** (PNG/JPEG/WebP images generated by Gemini/Imagen, binary PDF reports generated by No-Code `docgen_agent` or custom ADK agents via `tool_context.save_artifact()`, and compiled multi-slide HTML presentations from interactive Canvas `save_slides_to_artifact` tool calls)
5. **NotebookLM Enterprise Sources (`NOTEBOOK_SOURCE`) & 12-Modality Studio Artifacts (`NOTEBOOK_STUDIO_ARTIFACT`)** (PDFs, Markdown/text, Google Drive files, YouTube videos, web URLs, and Agentspace sources attached to notebooks, plus all 12 Studio modalities — Audio Overviews `.mp3`, Video Overviews `.mp4`, Slide Decks `.pdf`, Infographics `.png`, Reports, Flashcards, Quizzes, Mind Maps, Study Guides, FAQs, Timelines, Briefing Docs, and Studio Notes downloaded via Discovery Engine's Scotty `:download?alt=media` endpoint)
6. **Spoliation Prevention & Drift-Safe Custom IAM Role (`geUserNoDelete`)** (prevents users from deleting chat history or session attachments prior to harvest while automatically staying in sync with Google updates to `roles/discoveryengine.user`)
7. **Cryptographic Chain-of-Custody Metadata** (`SHA-256`, `CRC32C`, byte sizes, word/token counts, MIME types, and immutable Cloud Storage URIs)
8. **BigQuery Security & Forensic Reporting + Self-Contained Compliance Review Portal (`portal/`)** (automated jailbreak/prompt-injection detection, NotebookLM Enterprise forensic views, parameterized user forensic dossiers, and a React 18 Legal Brief Narrative UI deployed on Cloud Run)
9. **Microsoft Purview eDiscovery & DSPM for AI Integration (`purview_connector.py`)** (dual-track Microsoft Graph pipeline pushing self-contained HTML Legal Briefs + native binary `#microsoft.graph.fileAttachment` payloads into the custodian's Exchange Online `Gemini Enterprise eDiscovery` mailbox folder for Purview eDiscovery Content Search, Custodian Legal Holds, and Review Sets, plus `dataSecurityAndGovernance/processContent` for Purview DSPM for AI Activity Explorer & Audit)

This solution provides a complete, zero-browser-plugin, server-side pipeline that captures, archives, and indexes every Gemini Enterprise conversation turn, binary file attachment, and NotebookLM Enterprise interaction into **Google Cloud Storage**, **BigQuery**, and **Microsoft Purview eDiscovery**, paired with a self-contained **Compliance & Legal Brief Review Portal** on Cloud Run.

## Why a Special Architecture is Required

When a user authenticates to Gemini Enterprise or NotebookLM Enterprise via **Workforce Identity Federation (WIF)**, Discovery Engine binds every conversation session (`sessions/{sessionId}`), session file (`fileId`), and private notebook (`notebooks/{notebookId}`) exclusively to that user's federated principal (`principal://iam.googleapis.com/locations/global/workforcePools/<YOUR_WORKFORCE_POOL_ID>/subject/<USER_SUBJECT>`):

- **The Admin Ownership Barrier (`HTTP 403`)**: Standard Google Cloud IAM Project Owners or `roles/discoveryengine.admin` principals **cannot** call `GetSession`, `:downloadFile`, or `notebooks:listRecentlyViewed` / `notebooks.get` on a Workforce Identity user's private session or notebook. Attempting to do so with an admin OAuth token returns:
  ```text
  HTTP 403 PERMISSION_DENIED: Session is not owned by the provided user.
  ```
- **The Spoliation Window (`DeleteSession` Before Harvest)**: Standard `roles/discoveryengine.user` grants `discoveryengine.sessions.delete` and `discoveryengine.sessions.removeContextFile`. Because raw uploaded/generated binary files (`:downloadFile`) and untruncated $>64\text{ KiB}$ transcripts (`GetSession`) reside inside the user's Discovery Engine session until harvested, a user with `roles/discoveryengine.user` could delete a chat session immediately after generating or uploading sensitive material.
- **Cloud Logging Payload Truncation & Separate Sub-Product Streams**:
  - While enabling `observabilityEnabled=true` and `sensitiveLoggingEnabled=true` on Gemini Enterprise engines emits real-time `discoveryengine.googleapis.com/gemini_enterprise_user_activity` logs, those log entries only contain **metadata and file IDs** (`fileId`, `fileName`, `mimeType`)—not the raw binary bytes of uploaded documents or AI-generated images/PDFs/slides.
  - **NotebookLM Enterprise** does not run through `AssistantService.StreamAssist` or store artifacts under `engines/*/sessions/*`. Instead, it uses a separate project-level `customerProvidedConfig.notebooklmConfig.observabilityConfig` setting, emits logs to a separate `discoveryengine.googleapis.com/notebooklm_enterprise_user_activity` stream (`NotebookService.GenerateFreeFormStreamed`, `SourceService.BatchCreateSources`, `AudioOverviewService.*`), and stores notebooks under `projects/*/locations/*/notebooks/*`.

1. **Engine-Level, Agent-Level & Project-Level Sensitive Logging (`enable_ge_sensitive_logging.py`)**:
   - Patches all Gemini Enterprise engines (`global`, `us`, `eu`) to enable `observabilityEnabled=true` and `sensitiveLoggingEnabled=true`.
   - Iterates through every custom Agent (`lowCodeAgentDefinition`, `adkAgentDefinition`, `a2aAgentDefinition`) under `engines/{engine_id}/assistants/default_assistant/agents` and patches `observabilityConfig` on each agent individually.
   - Patches the Project-level NotebookLM Enterprise configuration (`v1alpha/projects/{project_id}` -> `customerProvidedConfig.notebooklmConfig.observabilityConfig`) across `global`, `us`, and `eu`.
2. **Cloud KMS-Backed Server-Side WIF Archiver OIDC Provider (`setup_ediscovery_archiver_provider.py`)**: Provisions a **Google Cloud KMS Asymmetric Signing Key** (`ge-ediscovery-kr` / `ediscovery-archiver-jwt-key`, algorithm `RSA_SIGN_PKCS1_2048_SHA256`), extracts its public key into `archiver_jwks.json` (`kid: "archiver-kms-key-1"`), and registers the `ediscovery-archiver` OIDC provider inside your Workforce Identity Pool with a strict CEL `--attribute-condition` (`assertion.iss`, `assertion.aud`, `assertion.sub != ''`). **No private key ever exists on disk or inside a container**—the harvester calls Cloud KMS `:asymmetricSign` over IAM-authenticated HTTPS to mint short-lived, per-user WIF STS tokens (`google.subject = assertion.sub`). *(Also includes optional keyless Google Workspace Domain-Wide Delegation fallback via `mint_dwd_token()` scoped strictly to `discoveryengine.readwrite` if non-WIF Workspace engines are used).*
3. **Immutable Cloud Storage + BigQuery Provisioning (`setup_storage_and_bigquery.py`)**: Creates a versioned, Uniform Bucket-Level Access (UBLA) GCS bucket with Public Access Prevention enforced (`--public-access-prevention`), a BigQuery dataset (`ge_ediscovery`), the `conversation_turns` table (loaded via atomic BigQuery `MERGE` from a staging table to prevent race conditions or spoliation), a real-time Cloud Logging sink capturing both `gemini_enterprise_user_activity` and `notebooklm_enterprise_user_activity`, and five ready-to-use BigQuery reporting views/functions (`v_ediscovery_file_audit`, `v_realtime_agent_and_file_activity`, `v_notebooklm_forensic_audit`, `v_jailbreak_and_security_detections`, and `fn_user_forensic_report`).
4. **Real-Time Event-Driven Cloud Run Harvester & Pub/Sub Dead-Letter Queue (`deploy_cloudrun_harvester.py`, `cloudrun_harvester_server.py`, `ge_harvest.py`, `scripts/replay-dlq.sh`)**:
   - **Real-Time Event-Driven Mode (`<10s` latency)**: A Cloud Logging sink (`ge-ediscovery-pubsub-sink`) streams `StreamAssist`, `Assist`, `UploadSessionFile`, `AddContextFile`, `GenerateFreeFormStreamed`, `BatchCreateSources`, `CreateNotebook`, `AudioOverviewService.*`, and `NotebookService.*` log entries to Pub/Sub (`ge-ediscovery-events`), which pushes each event via an OIDC-authenticated subscription (`ge-ediscovery-push-sub`) to the private Cloud Run service (`ge-ediscovery-harvester`, `--no-allow-unauthenticated`). Any unprocessable event after 10 delivery attempts is captured in `ge-ediscovery-dlq` (`ge-ediscovery-dlq-hold`) for inspection and replay via `scripts/replay-dlq.sh`.
   - **Gemini Enterprise, Custom Agents & Interactive Canvas**: Mints a per-user WIF STS token via Cloud KMS `:asymmetricSign`, fetches full untruncated `GetSession?includeAnswerDetails=true` transcripts, downloads all `USER_PROVIDED` and `AI_GENERATED` files via `:downloadFile`, inspects magic bytes (`detect_mime_and_extension`) to upgrade generic `application/octet-stream` payloads, compiles interactive Canvas `save_slides_to_artifact` tool calls into standalone multi-slide HTML presentations (`extract_canvas_slides`), computes `SHA-256` and `CRC32C` digests, and archives to GCS + BigQuery.
   - **NotebookLM Enterprise (Sources, Chat & 12-Modality Studio)**: Mints a per-user WIF STS token via Cloud KMS `:asymmetricSign` to call `notebooks.get`, `notebooks.sources.get`, `audioOverviews`, and `notes`, downloads binary Studio media (`.mp3`, `.mp4`, `.pdf`, `.png`) via Discovery Engine's Scotty `/download/v1alpha/{name}:download?alt=media` endpoint, deduplicates streamed reply chunks (`clean_notebooklm_streamed_reply`), archives content-addressed `notebook_archive_<sha256>.json` and Studio artifacts to `gs://<BUCKET>/notebooks/{location}/{notebook_id}/`, and loads an immutable `turn_index = 0` inventory row plus timestamp-addressed chat turns, `NOTEBOOK_SOURCE` records, and `NOTEBOOK_STUDIO` records into BigQuery.
5. **Spoliation Prevention & Drift-Safe Custom No-Delete Role (`setup_no_delete_role.py`, `sync_no_delete_role.py`, `scripts/swap-user-role.sh`, `scripts/sync-custom-role.sh`)**:
   - Provisions the custom role `projects/<YOUR_GCP_PROJECT_ID>/roles/geUserNoDelete` with every testable permission from `roles/discoveryengine.user` **except** `discoveryengine.sessions.delete` and `discoveryengine.sessions.removeContextFile`, and swaps your Workforce Identity Pool principal non-authoritatively (with automatic IAM backup and 1-command `--rollback`).
   - Provides a Two-Layer Delete-Guard synchronization script (`sync_no_delete_role.py` / `scripts/sync-custom-role.sh`) that compares `roles/discoveryengine.user` against `geUserNoDelete`, allowing you to safely merge new read/chat/agent permissions added by Google over time without ever re-introducing session or file deletion capabilities.
6. **Self-Contained Compliance & Legal Brief Narrative Review Portal (`portal/`, `deploy_portal.py`)**:
   - Deploys a single self-contained Cloud Run service (`ge-ediscovery-portal`, `--no-allow-unauthenticated`, `--iap` enabled by default, fail-closed `ALLOWED_REVIEWER_EMAILS` / `ALLOWED_REVIEWER_DOMAINS` RBAC) running under a dedicated read-only service account (`ge-ediscovery-portal-sa` with zero KMS signing or write permissions) that serves both the compiled React 18 Legal Brief Narrative SPA (`portal/dist`) and the Python BigQuery/GCS API (`portal/server.py`) with structured Cloud Logging access audit logs (`ediscovery_portal_access_audit`) and strict Content-Security-Policy headers.
   - Features side-by-side **Session Metadata**, **Turn Reasoning (`thought_text`)**, **File Provenance Box** (`SHA-256 Integrity`, `CRC32C Integrity`, `GCS Archive Path`, `Original File ID`, `MIME Type`, `Size`), inline PDF / sandboxed HTML Slide Deck / Image / Audio / Video playback (with chunked HTTP `206 Partial Content` `Range` streaming), and dedicated **NotebookLM Enterprise** tabs (**Sources**, **Chat**, and **Studio**).
7. **Microsoft Purview eDiscovery & DSPM for AI Connector (`purview_connector.py`)**:
   - **Track 1 — Purview eDiscovery Compliance Journal / Mailbox Substrate**: Resolves Entra ID UPNs or Object ID GUIDs (`google.subject = assertion.oid`), writes immutable compliance copies into a dedicated non-custodian compliance journal mailbox (`PURVIEW_COMPLIANCE_JOURNAL_UPN` under Legal Hold / Preservation Lock) or hidden Exchange compliance folder (`isHidden: true`), deduplicates via `internetMessageId` (`X-GE-Session-ID` + `X-GE-Turn-Index`), stamps MAPI `PidTagMessageClass` (`String 0x001A` via `PURVIEW_MESSAGE_CLASS`) and `X-GE-*` headers, renders a self-contained HTML Legal Brief, attaches inline binaries `<= 3 MiB` (`#microsoft.graph.fileAttachment`), and uploads large binary attachments `> 3 MiB` (up to `150 MiB`) in `3.75 MiB` chunks via Microsoft Graph `createUploadSession` (failing closed to Pub/Sub DLQ on delivery error).
   - **Track 2 — Microsoft Purview DSPM for AI & Audit (`processContent` API)**: Calls `POST /v1.0/users/{upn}/dataSecurityAndGovernance/processContent` with `#microsoft.graph.processConversationMetadata` (`uploadText` for user prompt, `downloadText` for model response, `accessedResources_v2` for file URIs).

### Step 7: Swap the Gemini Enterprise User Role & Keep Permissions in Sync

Because file bytes (`:downloadFile`) and $>64\text{ KiB}$ untruncated turns (`GetSession`) reside in the user's Discovery Engine session until harvested, a user with the standard `roles/discoveryengine.user` role could delete a chat seconds after creating it.

`scripts/swap-user-role.sh` (backed by `setup_no_delete_role.py`) creates a custom role `projects/<YOUR_GCP_PROJECT_ID>/roles/geUserNoDelete` containing all permissions from `roles/discoveryengine.user` **minus** `discoveryengine.sessions.delete` and `discoveryengine.sessions.removeContextFile`, additively binds it to your Workforce Identity Pool principal, backs up your project IAM policy, and removes `roles/discoveryengine.user` **only** from that single principal (leaving all other members of `roles/discoveryengine.user` untouched):

```bash
# 1. Dry run (creates/updates geUserNoDelete, grants it additively, and checks bindings):
scripts/swap-user-role.sh "$GCP_PROJECT_ID" "principalSet://iam.googleapis.com/locations/global/workforcePools/${WORKFORCE_POOL_ID}/*"

# 2. Apply (saves IAM backup and removes roles/discoveryengine.user from this principal):
scripts/swap-user-role.sh "$GCP_PROJECT_ID" "principalSet://iam.googleapis.com/locations/global/workforcePools/${WORKFORCE_POOL_ID}/*" --apply

# Optional: Restore standard roles/discoveryengine.user (re-enables chat deletion):
# scripts/swap-user-role.sh "$GCP_PROJECT_ID" "principalSet://iam.googleapis.com/locations/global/workforcePools/${WORKFORCE_POOL_ID}/*" --rollback
```

Whenever Google adds new permissions to the predefined `roles/discoveryengine.user` role over time, run `scripts/sync-custom-role.sh` (backed by `sync_no_delete_role.py`) to compare `roles/discoveryengine.user` against `geUserNoDelete` and safely patch in any new permissions while enforcing a two-layer Delete-Guard (blocking both the explicit denylist and any future `discoveryengine.(sessions|conversations|assistAnswers|turns).*(delete|remove|purge)` permissions):

```bash
# Check for permission drift between roles/discoveryengine.user and geUserNoDelete:
scripts/sync-custom-role.sh "$GCP_PROJECT_ID"

# Apply any newly added safe permissions to geUserNoDelete:
scripts/sync-custom-role.sh "$GCP_PROJECT_ID" --apply
```

It takes ~1–2 minutes for IAM changes to propagate. Afterward, users can chat, upload files, and run agents normally in the Gemini Enterprise UI, but attempting to delete a chat returns `HTTP 403 PERMISSION_DENIED`.

### Step 9: (Optional) Sync Gemini Enterprise Turns & Binary Attachments to Microsoft Purview eDiscovery (`purview_connector.py`)

For enterprises using **Microsoft Purview eDiscovery (Standard / Premium)** and **Purview DSPM for AI**, `purview_connector.py` pushes harvested Gemini Enterprise turns, reasoning traces (`thought_text`), and raw binary files (`USER_PROVIDED` uploads and `AI_GENERATED` PDFs/images/slides) into Microsoft 365 via two parallel Microsoft Graph tracks:
- **Track 1 — Purview eDiscovery Compliance Journal / Mailbox Substrate**: Writes an immutable, deduplicated item (`internetMessageId: <ge-ediscovery-{engine_id}-{session_id}-turn-{turn_index}@gemini.cloud.google.com>`) with MAPI `PidTagMessageClass` (`0x001A` via `PURVIEW_MESSAGE_CLASS`), searchable `X-GE-*` headers (`X-GE-Custodian-UPN`, `X-GE-Session-ID`, `X-GE-Turn-Index`), a self-contained HTML Legal Brief body, inline binaries `<= 3 MiB` (`#microsoft.graph.fileAttachment`), and chunked Microsoft Graph `createUploadSession` uploads (`3.75 MiB` chunks up to `150 MiB`) for binary attachments `> 3 MiB`.
- **Track 2 — Microsoft Purview DSPM for AI (`processContent`)**: Calls `POST /v1.0/users/{custodian_upn}/dataSecurityAndGovernance/processContent` with `#microsoft.graph.processConversationMetadata` (`uploadText` for user prompt, `downloadText` for model response, and `accessedResources_v2` for file URIs).

#### Purview Compliance Journal Mailbox (`PURVIEW_COMPLIANCE_JOURNAL_UPN`) vs. Custodian Email — How Installation Works

**Do administrators need to supply two emails per user?** **No.**
- **Custodian Email (Automatic Per Turn — Zero Manual Per-User Input):** Every turn's custodian UPN (e.g., `alice@example.com` or an Entra Object ID GUID resolved via `/users/{oid}`) is automatically extracted from the federated WIF `user_iam_principal` in BigQuery / Cloud Logging. Track 2 (`processContent`) always attributes activity directly to that custodian, and Track 1 always stamps `From` and `X-GE-Custodian-UPN` with that custodian's email so Purview KQL queries by user (`"alice@example.com"`) continue to work identically.
- **Target Mailbox for Track 1 Storage (Two Supported Modes):**
  1. **Recommended Anti-Spoliation Mode (One Tenant-Wide Compliance Journal Mailbox):** Set `PURVIEW_COMPLIANCE_JOURNAL_UPN="ediscovery-journal@example.com"` once at install time to a single dedicated, non-custodian Exchange Online shared/compliance mailbox protected by Microsoft 365 Litigation Hold + Preservation Lock (with zero end-user login or delegate permissions). All custodian turns across the organization are archived into that single locked mailbox, preventing a custodian who is not yet on individual litigation hold from deleting items out of their own mailbox.
  2. **Backward-Compatible Custodian Folder Mode (Default When Unset):** If `PURVIEW_COMPLIANCE_JOURNAL_UPN` is omitted, `purview_connector.py` defaults to archiving into a hidden folder (`PidTagAttributeHidden` / `isHidden: true`, named `Gemini Enterprise eDiscovery`) inside each custodian's own Exchange mailbox—requiring **zero configuration changes** for existing deployments, while logging a reminder to enforce an org-wide Microsoft Purview retention/hold policy on custodian mailboxes.

```bash
# 1. Recommended Production Mode: Archive all turns into one locked compliance journal mailbox
#    (Custodian UPNs are still auto-detected per turn from WIF user_iam_principal!)
PURVIEW_COMPLIANCE_JOURNAL_UPN="ediscovery-journal@example.com" \
python3 purview_connector.py \
  --project-id "$GCP_PROJECT_ID" \
  --tenant-id "$MS_TENANT_ID" \
  --client-id "$MS_CLIENT_ID" \
  --limit 50

# 2. Backward-Compatible Mode (or CLI Ad-Hoc Test Override for a single test custodian):
python3 purview_connector.py \
  --project-id "$GCP_PROJECT_ID" \
  --engine-id "$GE_ENGINE_ID" \
  --target-custodian-upn "custodian@example.com" \
  --limit 50
```

Once synced (or streamed automatically by `ge_harvest.py` when `MS_TENANT_ID` credentials are configured, with `PURVIEW_FAIL_CLOSED=true` returning HTTP `500` so Pub/Sub retries / DLQs transient Microsoft Graph failures), compliance investigators can search, place legal holds on, and add Gemini Enterprise interactions directly into **Purview eDiscovery Review Sets** inside the Microsoft Purview portal using KQL queries such as:
- All Gemini Enterprise turns: `"Gemini Enterprise eDiscovery"`
- Specific Custodian UPN (works in both Journal Mailbox and Custodian Folder modes): `"Gemini Enterprise eDiscovery" AND "alice@example.com"`
- Specific Session ID: `"<SESSION_ID>"`
- Turns with binary PDF/image/audio/video attachments (including `> 3 MiB` upload-session files): `"Gemini Enterprise eDiscovery" AND HasAttachment:true`

## Upgrading an Existing Customer GCP Deployment (Zero-Downtime Migration Guide)

If you have already installed an earlier release of `ge-ediscovery-logging` in a customer GCP project, **you do not need to recreate your Cloud Storage bucket, BigQuery dataset, Cloud KMS key, or Workforce Identity Pool**. Existing historical archive blobs and `conversation_turns` rows remain 100% intact.

### Summary of Security, Anti-Spoliation & Reliability Upgrades
1. **BigQuery Evidence Preservation & Greenfield Safety (`setup_storage_and_bigquery.py`, `ge_harvest.py`)**:
   - **72-Hour Session File Preservation**: `load_turns_to_bigquery` now unions existing `T.files` with newly harvested `S.files` (`COALESCE` by `file_id` / `gcs_uri`) during atomic `MERGE`, preventing re-harvests after Discovery Engine's ~72-hour session file TTL from overwriting earlier `USER_PROVIDED` file metadata with an empty array.
   - **30-Day NotebookLM Turn Preservation**: NotebookLM chat turns now compute deterministic positive 31-bit hashes (`compute_notebook_turn_index(timestamp, prompt_text)`) instead of re-numbering sequentially (`1..N`) from the 30-day Cloud Logging window, preventing older turns from being overwritten.
   - **Content-Addressed Transcript Snapshots**: Session and NotebookLM raw JSON snapshots are now stored at `session_transcript_<sha256[:16]>.json` and `notebook_archive_<sha256[:16]>.json` (while preserving backward compatibility with legacy filenames) and GCS bucket provisioning honors `--no-versioning` alongside WORM retention locks.
   - **Greenfield `INFORMATION_SCHEMA` Guard & New Custodian View**: `setup_storage_and_bigquery.py` checks `INFORMATION_SCHEMA.TABLES` before referencing raw Cloud Logging sink tables (eliminating `Not found: Table ... gemini_enterprise_user_activity` errors on fresh projects before the first user chat) and adds `v_ediscovery_custodian_export` (filtering out internal `ediscovery-smoke-*` / `test@example.com` verification rows).
2. **Least-Privilege IAM & WIF Subject Scoping (`deploy_cloudrun_harvester.py`, `ge_harvest.py`, `cloudrun_harvester_server.py`)**:
   - Replaces `roles/storage.objectAdmin` on `ge-ediscovery-harvester-sa` with `roles/storage.objectCreator` + `roles/storage.objectViewer` (write-once/read-many—the harvester cannot delete archived GCS evidence).
   - Enforces `ARCHIVER_ALLOWED_SUBJECT_DOMAINS` / `ARCHIVER_DENIED_SUBJECTS` before Cloud KMS signing, validates OIDC caller emails on `/pubsub` and `/sweep`, and passes `MS_CLIENT_SECRET` via Cloud Secret Manager (`--set-secrets`) instead of plaintext `--set-env-vars`.
3. **Microsoft Purview Legal Hold & Large Attachment Support (`purview_connector.py`)**:
   - Adds optional `PURVIEW_COMPLIANCE_JOURNAL_UPN` (single locked compliance mailbox across the tenant, backward-compatible with custodian hidden folders if unset), Microsoft Graph `createUploadSession` chunked uploads for binary attachments `> 3 MiB` (up to `150 MiB`), hidden folder creation (`isHidden: true`), and fail-closed Pub/Sub DLQ retry semantics.
4. **Compliance Review Portal Security & Scale (`deploy_portal.py`, `portal/`)**:
   - Enforces server-side JWT `aud` validation (`IAP_AUDIENCE`) via in-memory `cryptography` verification, fail-closed `ALLOWED_REVIEWER_EMAILS` / `ALLOWED_REVIEWER_DOMAINS` RBAC, dataset-scoped BigQuery `READER` permissions (instead of project-wide `bigquery.dataViewer`), `1Gi` container memory with chunked HTTP `206 Partial Content` `Range` media streaming, server-side BigQuery `/api/search` beyond the initial 2,000-turn UI window, and `dompurify@3.4.17` terminal sanitization with read-beacon-blocking `img-src data: blob:` slide CSP.

## BigQuery SQL Reporting & Forensic Queries

Once `setup_storage_and_bigquery.py` and `ge_harvest.py` have run, eight complementary SQL interfaces are available in BigQuery under `<YOUR_GCP_PROJECT_ID>.ge_ediscovery`.

### 1. File-Level Chain-of-Custody Audit Trail (`v_ediscovery_file_audit`)

Unnests the `files` array in `conversation_turns` so compliance reviewers can filter by `USER_PROVIDED`, `AI_GENERATED`, or `NOTEBOOK_SOURCE`, inspect `SHA-256` / `CRC32C` hashes, and click `console_url` to view or download the exact artifact from Cloud Storage:

```sql
SELECT
  event_timestamp,
  user_iam_principal,
  engine_id,
  session_id,
  turn_index,
  file_source,
  file_name,
  mime_type,
  byte_size,
  sha256,
  gcs_uri,
  console_url,
  SUBSTR(prompt_text, 1, 120) AS prompt_preview,
  SUBSTR(response_text, 1, 120) AS response_preview
FROM `<YOUR_GCP_PROJECT_ID>.ge_ediscovery.v_ediscovery_file_audit`
ORDER BY event_timestamp DESC, turn_index ASC;
```

### 2. Full Turn-by-Turn Conversation & Model Reasoning Transcript (`conversation_turns`)

Retrieves every conversation turn across all users, Gemini Enterprise engines, and NotebookLM Enterprise notebooks, including full untruncated prompts, responses, internal model reasoning (`thought_text`), and links to the raw `GetSession` (`session_transcript_<sha256>.json`) or `notebook_archive_<sha256>.json` transcript in Cloud Storage:

```sql
SELECT
  event_timestamp,
  user_iam_principal,
  engine_id,
  session_id,
  turn_index,
  prompt_text,
  response_text,
  thought_text,
  ARRAY_LENGTH(files) AS attached_file_count,
  session_transcript_console_url
FROM `<YOUR_GCP_PROJECT_ID>.ge_ediscovery.conversation_turns`
ORDER BY event_timestamp DESC, session_id, turn_index ASC;
```

### 3. Real-Time Agent & File Activity View (`v_realtime_agent_and_file_activity`)

When a custom Agent (such as a No-Code Agent) delegates PDF creation to `docgen_agent`, Discovery Engine logs two separate events in `gemini_enterprise_user_activity`:
- An `AddContextFile` row against the **Session** (`sessions/{id}`) containing `response.fileName`, `response.fileId`, `response.mimeType`, and `response.byteCount` (without `agentInfo.spiffeId`).
- A `StreamAssist` row 2 milliseconds later containing `response.agentInfo.spiffeId`, `request.query.parts[0].text` (the prompt), and `serviceTextReply`.

`v_realtime_agent_and_file_activity` automatically joins `StreamAssist` rows with `AddContextFile` / `UploadSessionFile` rows by `session_id`, normalizes both `query.text` (`core_assistant`) and `query.parts[0].text` (custom agents), and includes direct Cloud Storage links (`gcs_uri` and clickable `console_url`):

```sql
SELECT
  timestamp,
  user_iam_principal,
  session_id,
  agent_display_name,
  agent_spiffe_id,
  user_prompt,
  service_text_reply,
  file_source,
  file_name,
  mime_type,
  byte_count,
  gcs_uri,
  console_url,
  session_transcript_console_url
FROM `<YOUR_GCP_PROJECT_ID>.ge_ediscovery.v_realtime_agent_and_file_activity`
ORDER BY timestamp DESC
LIMIT 50;
```

You can also query the underlying raw Cloud Logging partitioned sink table (`discoveryengine_googleapis_com_gemini_enterprise_user_activity`) directly:

```sql
SELECT
  timestamp,
  jsonPayload.useriamprincipal AS user_iam_principal,
  jsonPayload.logmetadata.methodname AS method_name,
  COALESCE(
    jsonPayload.usertextquery,
    jsonPayload.request.query.text,
    jsonPayload.request.query.parts[SAFE_OFFSET(0)].text
  ) AS user_text_query,
  jsonPayload.servicetextreply AS service_text_reply,
  jsonPayload.response.fileid AS file_id,
  jsonPayload.response.filename AS file_name,
  jsonPayload.response.mimetype AS mime_type,
  CASE
    WHEN jsonPayload.logmetadata.methodname = 'UploadSessionFile' THEN 'USER_PROVIDED'
    WHEN jsonPayload.logmetadata.methodname = 'AddContextFile'    THEN 'AI_GENERATED'
    ELSE NULL
  END AS file_source
FROM `<YOUR_GCP_PROJECT_ID>.ge_ediscovery.discoveryengine_googleapis_com_gemini_enterprise_user_activity`
ORDER BY timestamp DESC
LIMIT 50;
```

### 4. Automated Jailbreak, Prompt Injection & Exfiltration Detection (`v_jailbreak_and_security_detections`)

Scans user prompts (`prompt_text`), model responses (`response_text`), and internal model thoughts (`thought_text`) across five security categories:
1. **Authority Spoofing (`AUTHORITY_SPOOFING`)** (`official directive`, `office of the ciso`, `authorized security test`, `override policy`)
2. **Instruction / Tool Override (`INSTRUCTION_OR_TOOL_OVERRIDE`)** (`ignore previous instructions`, `do not call any other tools`, `system prompt`, `DAN mode`, `jailbreak`, `bypass`)
3. **Obfuscated / Encrypted Payload (`OBFUSCATED_OR_ENCRYPTED_PAYLOAD`)** (`encrypted instruction`, `decrypt_instruction`, `ciphertext`, `aes-256-gcm`, `base64.b64decode`)
4. **Exfiltration / Sensitivity Label Probing (`EXFIL_OR_SENSITIVITY_LABEL_PROBE`)** (`external network callback`, `save it to my sharepoint`, `sensitivitylabel`, `purview`)
5. **Model Safety / DLP Refusal (`MODEL_SAFETY_OR_DLP_REFUSAL`)** (detects when the model's response or `thought_text` refuses an unsafe request or flags access/policy blocks)

```sql
SELECT
  event_timestamp,
  risk_severity,
  matched_threat_signals,
  model_refused_or_blocked,
  user_iam_principal,
  engine_id,
  session_id,
  turn_index,
  prompt_text,
  SUBSTR(response_text, 1, 200) AS response_preview,
  SUBSTR(thought_text, 1, 200) AS thought_preview,
  file_count,
  session_transcript_console_url
FROM `<YOUR_GCP_PROJECT_ID>.ge_ediscovery.v_jailbreak_and_security_detections`
WHERE risk_severity != 'LOW'
ORDER BY
  CASE risk_severity WHEN 'CRITICAL' THEN 1 WHEN 'HIGH' THEN 2 WHEN 'MEDIUM' THEN 3 ELSE 4 END,
  event_timestamp DESC;
```

### 8. Real-Time Raw NotebookLM Enterprise Cloud Logging Sink Query (`discoveryengine_googleapis_com_notebooklm_enterprise_user_activity`)

Queries the raw Cloud Logging partitioned sink table directly to inspect `CreateNotebook`, `GetNotebook`, `BatchCreateSources` (including failed external URL ingestions in `status.message`), and `GenerateFreeFormStreamed` events in real time:

```sql
SELECT
  timestamp,
  REGEXP_EXTRACT(jsonPayload.useriamprincipal, r'/subject/([^/]+)$') AS user_subject,
  jsonPayload.logmetadata.location AS location,
  jsonPayload.logmetadata.methodname AS method_name,
  COALESCE(
    REGEXP_EXTRACT(jsonPayload.request.name, r'/notebooks/([^/]+)$'),
    REGEXP_EXTRACT(jsonPayload.response.name, r'/notebooks/([^/]+)$'),
    REGEXP_EXTRACT(jsonPayload.request.parent, r'/notebooks/([^/]+)$')
  ) AS notebook_id,
  jsonPayload.response.title AS notebook_title,
  jsonPayload.request.userquery AS prompt_query,
  jsonPayload.servicetextreply AS streamed_reply_chunk,
  ARRAY_TO_STRING(
    ARRAY(SELECT src.title FROM UNNEST(jsonPayload.response.sources) AS src),
    ', '
  ) AS ingested_source_titles,
  jsonPayload.status.message AS error_or_url_ingestion_failure
FROM `<YOUR_GCP_PROJECT_ID>.ge_ediscovery.discoveryengine_googleapis_com_notebooklm_enterprise_user_activity`
ORDER BY timestamp DESC
LIMIT 100;
```
